## Зачем
Три дефекта, найденные на UI-приёмке v1.11.0 и существовавшие до неё. D4: сервер проверял персональный лимит по сумме цен за штуку без количества, и на стейдже прошёл заказ 740 ₽ при остатке 500 ₽. D2: при «Округлении итоговой суммы» цена округлялась вверх, а старая цена нет, поэтому «Ваша выгода» в корзине была занижена, а у товаров без скидки отрицательная. D1: покупатель с ролью «Менеджер», не руководящий подразделением, получал 404 «Поставка не найдена» на позицию своей заявки. Задача: без номера, дефекты D1, D2, D4 из отчёта приёмки v1.11.0.

## Изменения
- Лимит при оформлении заказа: сумма считается как Σ (цена × количество) с округлением каждой позиции до копеек, для всех аккаунтов. Раньше так считалось только для аккаунтов из `LIMIT_APPROVAL_ACCOUNT_IDS`, у остальных количество не учитывалось.
- Список товаров и товары с доступностью: при `account.priceRounding` старая цена (`originalPrice`, `originalPriceWithTaxes`) округляется вверх так же, как текущая. Округление текущей цены не менялось (`calculateBuyerPrice` из GARWIN-1488).
- `GET /api/supply/:id`: менеджер покупателя видит поставки подразделений, которыми руководит, и свои. Раньше видел только поставки подразделений, а без подразделений не видел ничего.
- Права на изменение поставки и смену статуса не менялись намеренно. По старому маршруту согласования только эта проверка не даёт автору-менеджеру согласовать свою заявку.

## Совместимость и выпуск
- Миграций нет.
- API: контракт не меняется, поведение совместимое.
  - `GET /api/supply/:id` использует только front-end (`API-USAGE.md`). Менеджеры покупателя теперь получают и свои поставки вместо 404.
  - `POST /api/good/list` используют front-end и pwa. У аккаунтов с `priceRounding` `originalPrice` и `originalPriceWithTaxes` теперь округлены, так что «выгода» исправится в обоих клиентах без их изменений.
- D4 строже: сервер отклоняет заказ сверх остатка лимита с учётом количества. Фронт и раньше проверял так же, поэтому в обычном сценарии пользователь разницы не заметит.
- Выкладка только back-end. Связанный MR front-end !18 (D3) независим, порядок не важен.
