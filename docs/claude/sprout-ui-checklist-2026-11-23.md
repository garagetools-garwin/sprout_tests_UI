# Приёмка Sprout !8 + !10

Запускать на изолированном локальном контуре с синтетическими ролями, dummy webhook и локальным приёмником уведомлений. Каждый сценарий начинает с чистой фикстуры. В отчёт записать SHA обоих компонентов, роль, ID синтетической записи, HTTP-статус и код, снимок UI и состояния БД до/после. Исключить заголовки авторизации и персональные данные. Все строки ниже требуют полноценной среды, кроме оговорённых отдельно проверок.

### Фикстуры

- Аккаунт A включён в LIMIT_APPROVAL_ACCOUNT_IDS, B выключен. Автор A1 без личного лимита и отдельный автор A2 с лимитом. Согласующий M1 с остатком 1 000 ₽ того же аккаунта, другой менеджер M2, менеджер другого аккаунта M3. Продавцы S1 и S2, менеджер S1 с доступом и коллега без договора. Два подразделения, одно со своим ненулевым общим лимитом и отдельный вариант с requestsConfirmation=false. Заполнить юрлицо, адрес, самовывоз и склад. Для проверок остатка отдельно задать 200 ₽, 199,99 ₽ и null.
- Товар T1 с текущей ценой 100 ₽ без НДС и старой ценой выше, T2 по 150 ₽ без НДС. В основных расчётах две единицы T1 дают 200 ₽. Для режимов использовать цены с налогом из ответа API. T3 без наличия и T4 только на разрешённом складе другого города. Для пагинации — минимум две страницы результатов, для города-сателлита — остатки у родителя. Отдельный self-registered покупатель.
- Для договора A/S1 задать default для пары и отдельный default для A, отличающиеся друг от друга. Договор A/S2 оставлять без сохранённого значения. Подготовить ещё покупателя без default и новый договор. Использовать отдельные браузерные сессии автора, согласующего и продавца.
